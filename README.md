# Qawaid (قواعد)

Learner app (Vite + React + Capacitor) with a FastAPI backend and Supabase. This README focuses on **running the admin panel** and **question types**.

For database migrations, RLS, and creating the first admin user in SQL, see **[supabase/README.md](supabase/README.md)**.

---

## Admin panel

### URL

- Local dev: `http://localhost:5173/admin` (or your Vite port).
- Production: `https://<your-domain>/admin`.

You are redirected to **`/admin/login`** until you authenticate.

### Who can access

- The account must exist in **Supabase Auth** (email + password).
- The same user id must exist in **`public.users`** with **`is_admin = true`**.
- The admin login form accepts a **username**; it is turned into an email using **`VITE_ADMIN_AUTH_DOMAIN`** (default in code: `admin.sahra.local`), e.g. user `admin` → `admin@admin.sahra.local`.

Set `VITE_ADMIN_AUTH_DOMAIN` in `.env` if you use a different email domain for admin accounts.

### Creating / fixing an admin account

1. In **Supabase Dashboard → Authentication → Users**, create a user with email `yourname@<your-admin-domain>` and a password (or use an existing user and ensure `public.users` matches).
2. In **SQL Editor**, ensure `public.users` has a row with **`id = auth user uuid`**, **`is_admin = true`**, and a **`username`** you will type on the login screen.

Full step-by-step (including sample `INSERT`) is in **[supabase/README.md](supabase/README.md)** under *Creating the first admin user*.

### Admin sections (tabs)

| Tab | Purpose |
|-----|---------|
| **Categories** | Topic buckets; link definitions to categories. |
| **Definitions** | Grammar terms / labels used in questions and distractors. |
| **Prompts** | Arabic sentences (`prompt_text`), difficulty, active flag; link words/letters to definitions via **prompt definitions** (including auto-link tools where available). |
| **Questions** | Question **templates** per category: text with `{definition}` placeholder, **type**, and active flag. The engine fills `{definition}` from the linked prompt. |
| **Reports** | User-reported issues on questions. |
| **Statistics** | Counts of content (e.g. questions by type). |
| **Config** | Session / JWT hints for admins. |

### Typical content flow

1. **Categories** → **Definitions** → attach definitions to categories (**category_definitions** — managed via the admin UI).
2. **Prompts**: add Arabic text, set difficulty, mark active; add **prompt definitions** (which word/letter maps to which definition).
3. **Questions**: add a template line with `{definition}` in the text, choose **category** and **type** (see below), enable **Active** if it should be eligible for play.

Correct answers for play are driven by **prompt_definitions** + definitions, not a separate “correct answer” field on the question row (see hint on the Questions form in the app).

## Question types

Types are stored in Postgres (`question_type` enum) and in the admin **Questions** dropdown. They are defined in code in **`src/types/db.ts`**.

### Used in live play today (batch engine)

The backend batch generator (**`backend/engine.py`**) only picks templates of these types when building a session:

| Type | Meaning |
|------|---------|
| **`MCQ`** | Multiple choice: several definition labels; user picks one. Prompt shows the target word/letter highlighted. |
| **`click_word`** | User taps the correct **word** in the Arabic prompt (prompt definition must **not** be letter-level). |
| **`click_letter`** | User taps the correct **letter** in the prompt (letter-level prompt definition). |
| **`click_letter_range`** | Like click letter, but uses a start/end range when `index_end` is set on the prompt definition; otherwise behaves like a single letter. |

Compatibility rules in the engine:

- Letter click types only apply when the chosen **prompt_definition** has **`is_letter = true`**.
- **`click_word`** only when **`is_letter = false`**.

### Present in admin / schema (not generated by the current batch engine)

These appear in the admin UI and database for future or alternate flows; **`generate_batch` does not select them today**:

| Type | Notes |
|------|--------|
| **`mcq_fillin`** | MCQ-style fill-in variant (DTO supports it; engine does not emit it yet). |
| **`visual_mcq`** | MCQ with image (`imageUrl` on DTO); engine does not emit it yet. |
| **`yes_no`** | Yes/no answer (`correctAnswerYesNo` in DTO). |
| **`fill_in_sentence`** | Typed word answer (`expectedWord` in DTO). |
| **`transformation`** | Transformation / expected word (`expectedWord`). |
| **`drag_and_match`** | Drag-and-match interaction (reserved in schema). |

If you add templates only of the “reserved” types, the batch may fail to find a matching template and return fewer or no questions—prefer **MCQ** and the **click_*** types for content that must appear in the main game loop.
